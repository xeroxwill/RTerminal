# RTerminal — дорожная карта форка

## Основа и статус

RTerminal начинается с исходного Android-приложения [Termux](https://github.com/termux/termux-app), зафиксированного на upstream-коммите `8629e632fcb95da272221be327db653fb24befe9`. Исходный репозиторий приложения отдельно указывает, что устанавливаемые через `pkg` пакеты живут в проекте [`termux-packages`](https://github.com/termux/termux-packages). Лицензия исходников приложения — GPLv3-only; сохранены исходные лицензионные файлы и уведомления.

В текущей ветке выполнен только начальный ребрендинг отображаемого имени приложения на **RTerminal**. Android package ID пока остаётся `com.termux`. Поэтому это ещё не самостоятельный APK, который можно установить рядом с Termux, и его нельзя считать готовым к выпуску.

## Цели продукта

- **Самостоятельное Android-приложение.** Перейти на собственный application ID RTerminal, не ломая внутренние пути, разрешения, службы и запуск shell.
- **Рабочий `pkg`.** Подготовить собственный bootstrap и совместимый репозиторий бинарных пакетов. Официальная документация Termux предупреждает, что смена package name требует пересборки bootstrap и бинарных пакетов под новый `$PREFIX`; одного изменения имени в Android-проекте недостаточно. См. [forking notes в исходниках Termux](https://github.com/termux/termux-app#forking) и [руководство для сопровождающих пакеты](https://github.com/termux/termux-packages/wiki/For-maintainers).
- **Стабильный Python из коробки.** Выбрать стабильную версию Python, закреплять её для каждого выпуска, включить согласованный пакет Python в начальный bootstrap и проверять обновление через `pkg`. Конкретная версия будет зафиксирована при подготовке пакетной инфраструктуры.
- **GUI-библиотеки.** Подготовить и проверять графическую сессию и пакеты для Tkinter, Dear PyGui (в запросе — PyDearGui), PyQt5, Qt, SDL2 и других выбранных библиотек. Успешная установка библиотеки сама по себе не означает, что приложение умеет показывать её окна: нужны совместимые зависимости и тесты на Android-устройстве.
- **Стабильность и память.** Собирать воспроизводимые замеры памяти и поведения процессов на целевых версиях Android, включая запуск, простой, возврат из фона и типовую работу в терминале. Снижать собственные накладные расходы RTerminal, не обещая контролировать системные ограничения Android.
- **Место на диске.** Оптимизировать размер APK, начального bootstrap, устанавливаемых пакетов, кэша и временных файлов. В исходном запросе указано снижение расхода с 20 ГБ до 10 ГБ, но не задано, что именно считается расходом и какие пакеты установлены. Эти числа пока являются пожеланием, а не измеренной характеристикой или гарантированным лимитом.

## Как измерять оптимизацию

Для каждого релиза отдельно фиксировать: размер скачанного APK; занимаемое приложением место после первого запуска; размер базового окружения; размер и число выбранных пользователем пакетов после `pkg`; объём кэша до и после очистки; использование RAM при запуске, простое и типовой нагрузке. Сравнение проводить на одинаковой модели устройства, версии Android, ABI и наборе пакетов относительно исходного Termux. Не удалять файлы или зависимости, необходимые пакетам, только ради меньшей цифры.

## Этапы

1. **Бренд и технический форк:** завершить название, иконку, ссылки на проект и отдельный application ID; проверить разрешения и запуск на физическом Android-устройстве.
2. **Собственный пакетный слой:** подготовить fork build-рецептов `termux-packages`, bootstrap для нового `$PREFIX`, репозиторий пакетов и автоматическую сборку для поддерживаемых ABI.
3. **Базовая поставка Python:** закрепить стабильную версию и включить её в начальную установку; проверить стандартные модули и обновление пакета.
4. **GUI-стек:** составить матрицу поддерживаемых Python GUI-пакетов и графических серверов/сессий; проверять их отдельно на устройстве.
5. **Стабильность и ресурсы:** получить исходные измерения, оптимизировать найденные узкие места и публиковать сравнение по воспроизводимой методике.
6. **Выпуск:** только после прохождения сборки, установки, обновления `pkg` и smoke-тестов GUI выпускать APK и публиковать конкретные проверенные цифры.
